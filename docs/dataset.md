# Датасет NEREL: исходный формат и представление для EDA

## Источник и границы описания

Источник: [danasone/nerel на Hugging Face](https://huggingface.co/datasets/danasone/nerel).
Загрузка по условию задания:

```python
from datasets import load_dataset

ds = load_dataset("danasone/nerel")["train"]
```

По просмотрщику источника на момент исследования (18 октября 2026 года)
доступен один split `train` с 746 записями. Эти сведения и примеры полей
проверены по веб-просмотрщику, а не локальным проходом по всему датасету.
При загрузке необходимо проверить фактические размер и схему.

Одна запись — один новостной документ с разметкой для двух задач:
распознавания именованных сущностей (NER) и определения применимости
30 характеристик документа (CLS). Характеристики не взаимоисключающие.

## Исходные поля

| Поле | Содержимое | Использование |
| --- | --- | --- |
| `text` | Исходный текст документа | Просмотр примеров, проверка символьных границ |
| `tokens` | Последовательность исходных слов | Единицы исходной BIO-разметки; ещё не субтокены RuBERT |
| `token_spans` | Пары символьных границ для элементов `tokens` | Проверка соответствия слов исходному тексту |
| `tags` | Последовательность строковых BIO-меток, соответствующих `tokens` | NER-таргет на уровне исходных слов |
| `cls_vec` | Вектор из 30 бинарных значений | Многометочный CLS-таргет документа |

В доступных примерах пунктуация может входить в элемент `tokens`,
например `Пулеметы,`. Повторное разбиение текста на слова может нарушить
соответствие с готовыми `tags` и `token_spans`.

BIO-разметка и CLS-вектор уже присутствуют в этой версии датасета.
Их не требуется заново строить из исходных аннотаций сущностей и отношений.
Нужно проверить их корректность и затем выровнять BIO-метки с субтокенами модели.

Порядок характеристик `cls_vec` берётся из условия курса; он зафиксирован
в `CLS_LABELS` в EDA-ячейке ноутбука. Названия вектора нельзя сортировать
независимо от его значений.

## Таблица `eda_df`

Реализация находится в EDA-разделе
[`NEREL_MultiTask_Notebook.ipynb`](../NEREL_MultiTask_Notebook.ipynb).
Таблица строится из переменной `ds`.

| Колонка | Тип Polars | Смысл |
| --- | --- | --- |
| `id` | `Int64` | Номер записи в текущем `ds`, начиная с 0 |
| `size` | `Int64` | `len(tokens)`: длина в исходных словах, а не субтокенах модели |
| `tags` | `Struct` с целочисленными полями | Число вхождений каждой BIO-метки в документе |
| `labels` | `Struct` с 30 целочисленными полями | Соответствие названия характеристики значению 0/1 из `cls_vec` |

`id` уникален внутри построенной таблицы, но не является идентификатором
из источника: перестановка или фильтрация `ds` перед построением изменит номера.

В `tags` сохраняется `O`, а `B-TYPE` и `I-TYPE` считаются отдельно.
Набор полей одинаков для всех строк: отсутствующая в документе метка получает 0.
Это частоты меток слов, а не число сущностей. Для корректной BIO-последовательности
число сущностей можно получить суммой частот `B-*`; предварительно нужно проверить
BIO-переходы. Для общей частоты слов определённого типа можно сложить `B-TYPE`
и `I-TYPE`.

Словари представлены нативными `Struct`-колонками Polars. Например:

```python
eda_df.select(pl.col("labels").struct.field("WORKPLACE").mean())
eda_df.select(pl.col("tags").struct.field("O").sum())
```

Текущая ячейка проверяет совпадение длин `tokens` и `tags`, а также длину
и бинарность `cls_vec`. Остальные проверки ниже пока не реализованы.

## Следующие шаги EDA

- Проверить пропуски, пустые документы и дубликаты текстов.
- Проверить длины `token_spans`, соответствие границ `text` и BIO-переходы.
- Построить распределения длин, числа сущностей и активных CLS-характеристик.
- Оценить частоты NER-типов, долю `O` и распространённость каждой CLS-характеристики.
- После подключения токенизатора отдельно измерить длины в субтокенах
  и долю данных, теряемых при выбранном ограничении длины.

## Предварительные последствия для обучения

- При одном исходном split потребуется воспроизводимое разбиение на обучение,
  валидацию и тест; дубликаты следует проверить до разбиения.
- `size` недостаточно для выбора `max_length`: модель использует субтокены.
- Готовые BIO-метки нужно переносить через связь слов с субтокенами,
  сохраняя исходное разбиение `tokens`.
- Один документ может иметь несколько CLS-характеристик; эти цели требуют
  независимых бинарных предсказаний.

Дисбаланс, качество разметки и конкретные потери от обрезания пока не измерены.
Количественные выводы и графики добавляются после выполнения EDA на полном наборе.
